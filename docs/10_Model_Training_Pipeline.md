# Model Training Pipeline

## Overview

The Model Training Pipeline is the process that trains the machine learning models used in the simulation. It takes the synthetic cohort data and trains models to predict blood pressure progression.

The pipeline trains two types of models:

1. **Baseline models**: Predict the initial MAP_z and PP_z from patient demographics and risk factors. These are used when a new patient enters the simulation.

2. **Progression models**: Predict the annual change in MAP_z and PP_z based on the current state. These are used each year of the simulation to advance the patient's blood pressure.

The pipeline is implemented in `models/pipeline.py` and runs automatically when the synthetic cohort is updated or when new models need to be trained.

## Scientific / Theoretical Basis

### Why Train Machine Learning Models?

Machine learning models can capture complex patterns in data that simple equations cannot. For blood pressure progression, factors like age, sex, waist circumference, kidney function, smoking, alcohol, and sodium all interact in complex ways. Machine learning models can learn these interactions from the synthetic cohort data.

### Why Ridge Regression for Baseline?

The baseline models use Ridge regression because:

- Some features are moderately correlated (e.g., waist and eGFR have correlation ~0.35)
- Ridge regression handles collinearity better than ordinary linear regression
- It prevents overfitting by adding a penalty term to the model
- It was introduced by Hoerl & Kennard (1970) [1]

### Why Compare Multiple Algorithms for MAP Progression?

For MAP progression, we compare three algorithms:

- **Ridge Regression**: Simple linear model with regularization
- **Random Forest**: Ensemble of decision trees that can capture nonlinear patterns
- **Gradient Boosting**: Another ensemble method that builds trees sequentially

We compare them using cross-validation (splitting the data into training and testing sets multiple times) and select the one with the highest cross-validation R² score. This ensures we pick the model that performs best on new data, not just the training data.

### Why Only Ridge for PP Progression?

For PP progression, we always use Ridge regression. This is based on the Franklin et al. (1999) study, which showed that pulse pressure increases at a relatively constant rate with age [2]. A simple linear model is sufficient for this more predictable pattern.

## Data Structures

### Training Data

The training data comes from the synthetic cohort generated by `generate_cohort.py`:

- **Location**: `data/synthetic_cohort/cohort.csv`
- **Rows**: Approximately 150,000 (5,000 patients × ~30 years each)
- **Columns**: Patient characteristics, blood pressure, and risk factors

### Baseline Features

The baseline models use these features to predict initial MAP_z and PP_z:

```
BASELINE_FEATURES = [
    "age",            # Patient age
    "sex",            # 1 for male, 2 for female
    "waist_cm",       # Waist circumference
    "heart_rate",     # Heart rate in bpm
    "egfr",           # Kidney function
    "pack_years",     # Cumulative smoking exposure
    "alcohol_g_day",  # Daily alcohol consumption
    "sodium_mg_day"   # Daily sodium intake
]
```

### Progression Features

The progression models use these features to predict annual changes:

```
PROGRESSION_FEATURES = [
    "map_z",          # Current MAP z-score
    "pp_z",           # Current PP z-score
    "age",            # Patient age
    "sex",            # 1 for male, 2 for female
    "waist_cm",       # Waist circumference
    "heart_rate",     # Heart rate in bpm
    "egfr",           # Kidney function
    "pack_years",     # Cumulative smoking exposure
    "alcohol_g_day",  # Daily alcohol consumption
    "sodium_mg_day"   # Daily sodium intake
]
```

### Trained Models

The pipeline saves trained models to the `models/` directory:

- **baseline_map.pkl**: Baseline model for MAP_z
- **baseline_pp.pkl**: Baseline model for PP_z
- **progression_map.pkl**: Progression model for MAP_z (best algorithm selected)
- **progression_pp.pkl**: Progression model for PP_z (Ridge regression)

## Step-by-Step Process

### Step 1: Load Synthetic Cohort

The pipeline loads the synthetic cohort data:

```python
df = pd.read_csv("data/synthetic_cohort/cohort.csv")
```

This data was generated by `generate_cohort.py` and contains realistic blood pressure trajectories.

### Step 2: Train Baseline Models

The pipeline extracts the baseline visit (year 0) for each patient:

```python
baseline = df[df.visit_year == 0]
```

It then trains two Ridge regression models:

```python
X = baseline[BASELINE_FEATURES]
y_map = baseline["map_z"]
y_pp = baseline["pp_z"]

map_model = Pipeline([("scaler", StandardScaler()), ("ridge", Ridge(alpha=1.0))])
pp_model = Pipeline([("scaler", StandardScaler()), ("ridge", Ridge(alpha=1.0))])

map_model.fit(X, y_map)
pp_model.fit(X, y_pp)
```

The StandardScaler normalizes the features (mean=0, std=1) before feeding them to the Ridge regression.

### Step 3: Validate Baseline Models

The pipeline checks the models' performance:

```python
map_r2 = r2_score(y_map, map_model.predict(X))
pp_r2 = r2_score(y_pp, pp_model.predict(X))
```

It also runs a sanity check with a typical patient profile to ensure the predicted blood pressure values are reasonable.

### Step 4: Build Transition Dataset for Progression

For progression models, the pipeline needs pairs of consecutive visits to learn how blood pressure changes over time:

```python
for each patient:
    for each consecutive year pair:
        current_state = features at year N
        next_state = features at year N+1
        delta_map_z = next_state.map_z - current_state.map_z
        delta_pp_z = next_state.pp_z - current_state.pp_z
```

This creates a dataset where each row represents one year of progression for one patient.

### Step 5: Compare Algorithms for MAP Progression

The pipeline trains three different algorithms on the MAP progression data:

```python
candidates = {
    "Ridge": Pipeline([("sc", StandardScaler()), ("m", Ridge(alpha=1.0))]),
    "Random Forest": RandomForestRegressor(n_estimators=100, max_depth=6),
    "Gradient Boosting": GradientBoostingRegressor(n_estimators=200, max_depth=4)
}
```

For each algorithm, it calculates:

- **Train R²**: How well the model fits the training data
- **CV R²**: How well the model generalizes to new data (5-fold cross-validation)

The algorithm with the highest CV R² is selected as the best model.

### Step 6: Train PP Progression Model

For PP progression, the pipeline always uses Ridge regression:

```python
pp_model = Pipeline([("sc", StandardScaler()), ("m", Ridge(alpha=1.0))])
pp_model.fit(X, y_pp)
```

### Step 7: Clinical Validation

The pipeline runs a clinical validation test using a specific patient profile (47-year-old female with SBP=168, DBP=102) to ensure the models produce realistic blood pressure trajectories over time.

### Step 8: Save Models

All trained models are saved to the `models/` directory:

```python
joblib.dump(map_model, "models/baseline_map.pkl")
joblib.dump(pp_model, "models/baseline_pp.pkl")
joblib.dump(best_map_model, "models/progression_map.pkl")
joblib.dump(pp_model, "models/progression_pp.pkl")
```

## Inputs and Outputs

### Inputs

The Model Training Pipeline takes:

- **Synthetic cohort**: CSV file at `data/synthetic_cohort/cohort.csv`
- **Feature lists**: Predefined lists of baseline and progression features
- **Algorithm configurations**: Hyperparameters for each machine learning algorithm

### Outputs

The pipeline produces:

- **Trained baseline models**: baseline_map.pkl, baseline_pp.pkl
- **Trained progression models**: progression_map.pkl, progression_pp.pkl
- **Performance metrics**: R² scores for each model
- **Validation results**: Clinical validation test results

## Design Decisions

### Why Use Cross-Validation?

Cross-validation splits the data into training and testing sets multiple times (5-fold means 5 different splits). This gives a more reliable estimate of how the model will perform on new data than a single train/test split. It helps prevent overfitting.

### Why StandardScaler Before Ridge?

Ridge regression works best when features are on similar scales. StandardScaler normalizes each feature to have mean=0 and std=1. This ensures that the regularization penalty is applied fairly across all features.

### Why These Hyperparameters?

The hyperparameters for each algorithm were selected based on common practices:

- **Ridge alpha=1.0**: Moderate regularization strength
- **Random Forest n_estimators=100, max_depth=6**: Enough trees for stability without overfitting
- **Gradient Boosting n_estimators=200, max_depth=4, learning_rate=0.05**: Conservative settings that prevent overfitting

### Why Quartile Validation?

The pipeline validates that the MAP progression model correctly predicts that patients with higher MAP_z have faster progression. It splits patients into quartiles by MAP_z and checks that the highest quartile has the fastest progression. This is a sanity check that the model has learned the correct pattern.

## Integration with Other Subsystems

The Model Training Pipeline connects to:

- **Synthetic BP Cohort Generation**: The synthetic cohort provides the training data for the models
- **Blood Pressure Progression Models**: The trained models are used in the simulation to predict blood pressure progression
- **Internal State Representation**: The models operate on MAP_z and PP_z, the internal state variables

The training pipeline is run whenever the synthetic cohort is updated or when new models need to be trained. The trained models are then loaded by the simulation engine in main.py.
